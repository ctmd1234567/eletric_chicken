# 恶劣天气下烟雾检测：研究借鉴与离线对照设计

## 依据与边界

借鉴 Gupta 等人在 WACV 2024 的论文 [Robust Object Detection in Challenging Weather Conditions](https://openaccess.thecvf.com/content/WACV2024/html/Gupta_Robust_Object_Detection_in_Challenging_Weather_Conditions_WACV_2024_paper.html)。论文在道路目标检测中比较真实全天气数据训练、合成天气增强训练，以及图像去天气后检测；在其数据与设置下，真实全天气训练表现最好，先去天气再检测表现最差。该结果不能直接推断车棚薄烟的效果，也不排除其他预处理有效。

转化为本项目的设计：优先收集有许可的真实车棚天气素材，保留原图检测基线；合成天气和去天气只作为未来有标签实验的对照，不默认加入推理链路。当前不训练、不添加预处理，也没有天气鲁棒性实测结果。

## 当前阶段：建立可复核基线

1. 按机位、日期和事件收集真实视频，记录来源与许可、天气（晴/雨/雾/雪/未知）、光照（白天/夜间/未知）、镜头状态（正常/水滴/污损/未知）及主要干扰（水汽、反光、尾气等）。天气、光照和干扰可同时出现；无法确认写未知。素材与标注留在本地，许可按 NOTICE 规则核实。
2. 以原始视频为输入，同一素材上的候选模型使用相同抽帧、置信度和连续帧规则，保留各模型实际输入尺寸和 NMS 配置。运行与标注格式见[视频基线](video_baseline.md)。例如：

   ```powershell
   .\.venv\Scripts\python.exe scripts/video_baseline.py --source video --device 0
   .\.venv\Scripts\python.exe scripts/evaluate_temporal.py --detections samples/video_results/run_001/detections.csv --annotations samples/video_results/run_001/annotations_reviewed.csv --consecutive 1 3 5 --out samples/video_results/run_001/reviewed_temporal
   ```

   将路径替换为本次实际结果；标注完成后才执行第二条。`manifest.json` 记录素材和权重哈希、参数及运行状态，人工维护独立的本地天气记录，以 `video_id` 关联；天气在视频内变化时须另记起止帧。现有脚本不会自动识别天气或按天气汇总，需人工关联 `temporal/frames.csv` 和 `smoke_segments.csv`，以帧号相交计算。关联时按视频、机位和事件核对，避免重复计数。
3. 人工逐区间标注 `smoke`、`clear`、`unknown` 和干扰源；只有确认真实起烟帧才填起烟时间。按天气及光照分别报告已标注烟雾片段告警比例、无烟帧告警比例、首次有效触发延迟、推理延迟以及各自分子、分母和视频/事件数。无标签或样本不足的分组标为待测；不能将有框帧占比当召回率。连续帧口径和起烟前误报处理沿用视频基线说明。
4. 天气与机位、距离、烟量和光照可能混杂。分组差异只能描述样本，不直接归因于天气；同一事件的相邻帧不是独立事件。素材筛选和分组规则先固定，再报告所有组和未知组，避免仅挑有利结果。

## 后续实验，尚未实施

- 数据按机位、日期及独立火情事件划分训练、验证和测试，避免同一事件或相邻帧跨集合；固定未见过的真实车棚天气测试集。训练材料许可、标注和足量样本具备后，比较相同模型与训练预算下的晴天数据、真实多天气数据、真实数据加合成天气增强。阈值只用验证集确定，测试集不调参。
- 若探索去雨、去雾或增强，对同一测试帧比较原图与处理后图，固定检测器、阈值及其他参数；记录算法版本、参数、处理失败和额外端到端延迟。薄烟可能被处理成背景或产生伪影，须人工检查；图像视觉质量不能代替烟雾检测和告警指标。
- 合成天气仅作为补充，记录生成方法、参数和随机种子，复核其是否遮挡或改变烟雾标注；不得把合成测试结果当作真实天气表现。分别给出晴天与各真实天气分组结果，避免总体平均掩盖退化。

这些是待执行方案，不能据此声称模型已具备恶劣天气预警能力。道路场景的论文结论需要通过车棚真实素材独立验证。
